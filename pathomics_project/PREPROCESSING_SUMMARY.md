## 1️⃣ 입력 데이터

### 원본 데이터셋: BCSS (Breast Cancer Semantic Segmentation)

| 항목 | 내용 |
|------|------|
| 출처 | TCGA-BRCA에서 추출한 H&E 염색 조직영상 |
| 전체 슬라이드 수 | 151장 |
| 다운로드 경로 | github.com/CancerDataScience/CrowdsourcingDataset-Amgadetal2019 |
| 원본 클래스 수 | 22개 (`meta/gtruth_codes.tsv` 기준, 실제 확인함) |
| 이미지 형식 | RGB PNG, 해상도 0.25 MPP |
| 마스크 형식 | PNG, 픽셀값이 클래스 인덱스 |

### 실측 데이터 특성 (87/151장 다운로드 후 확인)

- **이미지 크기가 슬라이드마다 다름**: 3394×2467, 4838×3426, 3794×2919 등 (균일하지 않음)
- **파일 용량**: 이미지 장당 평균 ~27MB, 마스크 장당 평균 ~110KB (전체 이미지 약 4GB, 마스크 약 16MB로 추정)
- **관측된 클래스값**: 1, 2, 3, 4, 5, 9, 13, 18 — 매핑 테이블에 정의된 범위 내에서 전부 확인됨

## 2️⃣ 전처리 문제점과 해결

### ❌ 문제 1: 22개 클래스가 너무 세분화됨
임상적으로 의미있는 5개 대분류(Tumor/Stroma/Immune/Necrosis/Other)로 통합 필요

**해결**: `meta/gtruth_codes.tsv` 원본을 직접 확인해서 정확한 22→5 매핑 테이블 작성 (추측 없이 원본 소스 기반)

### ❌ 문제 2: 이미지 크기가 통일되어 있지 않음
슬라이드마다 크기가 제각각이라 배치 학습 불가능

**해결**: 512×512 고정 크기 패치로 분할 (`extract_patches()`), 배경 위주 패치는 자동 제외

### ❌ 문제 3: 여러 기관/스캐너 출처라 염색 색감 편차 존재
같은 조직이라도 스캐너/염색 프로토콜에 따라 색이 다르게 나옴

**해결**: Macenko 염색 정규화 구현. 합성 데이터 검증 결과 서로 다른 색조의 두 이미지 간 조직 픽셀 색상 차이가 **70.06 → 2.02로 약 97% 감소**

### ❌ 문제 4: 패치 단위 분할 시 데이터 누수 위험
같은 환자의 패치가 train/test에 동시에 들어가면 성능이 부풀려짐

**해결**: 패치가 아니라 **환자(TCGA case ID) 단위로 먼저 분할**한 뒤, 그 안에서 패치 추출 (`split_by_case()`)

### ❌ 문제 5: 손상되거나 불완전한 이미지/마스크 처리
- 이미지-마스크 파일이 서로 짝이 안 맞는 경우
- 이미지와 마스크의 해상도가 다른 경우 (파일 손상 가능성)
- 마스크가 전부 배경/제외 클래스인 경우 (조직이 없는 슬라이드)
- 이미지 로드 자체가 실패하는 경우

**해결**: `preprocess_split()`에 4중 방어 로직 추가
1. `collect_pairs()`: 이미지-마스크 파일명 매칭 확인, 짝 안 맞는 파일은 제외 + 경고 로그
2. 이미지/마스크 로드 실패 시 예외 처리 후 해당 슬라이드 스킵 (전체 파이프라인 중단 방지)
3. 이미지-마스크 shape 불일치 시 조용히 잘못된 패치를 만들지 않고 명시적으로 스킵
4. 마스크가 전부 배경(class 0)인 경우 스킵 (학습에 기여 못하는 빈 데이터 배제)

## 3️⃣ 전처리 파이프라인 (5단계)

| Step | 내용 | 상태 |
|------|------|:---:|
| 1 | 이미지-마스크 페어 수집 및 매칭 검증 | ✅ 구현+실데이터 검증 |
| 2 | 클래스 분포 샘플 확인 | ✅ 구현+실데이터 검증 |
| 3 | 환자 단위 train/val/test 분할 | ✅ 구현 (합성데이터 검증) |
| 4 | 512×512 패치 분할 + 배경 필터링 | ✅ 구현+실측 크기 기준 검증 |
| 5 | Macenko 염색 정규화 + 픽셀 정규화 | ✅ 구현 (합성데이터 검증) |

## 4️⃣ 최종 클래스 매핑 (22개 → 5개)

| 대분류 | 포함 원본 클래스 |
|--------|-----------------|
| **Tumor** | tumor, angioinvasion, dcis |
| **Stroma** | stroma, normal_acinus_or_duct |
| **Immune** | lymphocytic_infiltrate, plasma_cells, other_immune_infiltrate, lymphatics |
| **Necrosis** | necrosis_or_debris |
| **Other** | glandular_secretions, blood, metaplasia_NOS, fat, mucoid_material, nerve, skin_adnexa, blood_vessel, other |
| *(배경/제외)* | outside_roi, exclude, undetermined |

## 5️⃣ 검증 현황 — 솔직한 상태

| 구성요소 | 합성 데이터 검증 | 실제 BCSS 데이터 검증 |
|---------|:---:|:---:|
| 클래스 매핑 함수 | ✅ | ✅ (샘플 3장 기준) |
| 패치 분할 로직 | ✅ | ⚠️ 실측 크기 기준 시뮬레이션만 완료, 실제 파일 미적용 |
| 염색 정규화 | ✅ (97% 색상차 감소) | ❌ 아직 |
| 환자 단위 분할 | ✅ | ❌ 아직 (실제 case ID 정규식 매칭 미확인) |
| 방어 로직 (예외처리) | ✅ (로직 단위 테스트) | ❌ 아직 |

**전체 파이프라인이 실제 BCSS 파일로 처음부터 끝까지 실행된 적은 아직 없습니다.** 코드는 완성되어 있고 각 구성요소는 개별 검증됐지만, 실제 데이터로 `python preprocess_bcss.py`를 돌려서 끝까지 확인하는 게 다음 단계입니다.
